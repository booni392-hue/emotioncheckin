# 스마트올 매일 마음체크인 — 공동 수정용 프로젝트

> 제공된 `index.html`을 **화면·설문·성향 결과·마음지도·효과음·시연 컨트롤러를 유지하도록** 정리한 버전입니다. 별도 프레임워크/빌드 명령이 필요하지 않습니다.

## 1. 처음 사용하는 방법 (마케터도 가능)

1. ZIP 파일을 압축 해제합니다.
2. [VS Code](https://code.visualstudio.com/)를 설치한 뒤 **파일 → 폴더 열기**로 `smartall-emotion-checkin` 폴더를 엽니다.
3. 왼쪽 `Extensions`에서 **Live Server**를 설치합니다. (`.vscode/extensions.json` 추천 확장)
4. `index.html`을 마우스 오른쪽 클릭 → **Open with Live Server**를 선택합니다.
5. 화면이 열리면 `js/config.js`의 문구를 수정하고 저장(`Ctrl+S`)합니다. 브라우저에서 갱신된 내용을 확인합니다.

> 간단히 확인할 때는 `index.html` 더블클릭으로도 실행할 수 있습니다. 다만 브라우저 제약을 피하려면 Live Server 사용을 권장합니다.

## 2. 파일별 담당자 / 수정 위치

| 파일 | 담당 권장 | 수정하는 것 |
|---|---|---|
| `js/config.js` | **마케터 / 기획자** | 아이 이름, Day 1~10 질문/선택지, 4개 성향 결과, 칭찬/피드백, 친구 별명, 인트로 문구 |
| `css/style.css` | 디자이너 / 기획자 | `:root` 색상, 글자 크기, 여백, 애니메이션 등 |
| `js/app.js` | 개발자 | 화면 전환, 점수 계산, 지도, 기록, 음향, 시연 로직 |

## 3. 실제로 수정하는 예시

### 아이 이름 바꾸기
`js/config.js` 최상단의 `const NAME="지민";`를 `const NAME="하늘";`처럼 변경하세요.

### Day 1 첫 번째 질문 수정
`js/config.js`에서 `1:{ q:[`를 찾으세요. 바로 아래 `intro`가 질문 문구입니다.
```js
{intro:`${NAME} 친구, 오늘 기분이 어때?`, mascot:"🌟",
 o:[["😊","신나요"],["😌","편안해요"],["😴","졸려요"],["🥺","속상해요"]],
 kind:"emo", topic:"오늘의 기분"},
```
문항에는 `intro`, `mascot`, `o`(선택지), `kind`, `topic`이 쓰입니다.

### 탐험가 소개 문구 변경
`const TYPES={` 아래 `0:{key:"A",name:"탐험가"`를 찾고 `desc`나 `retry`를 수정하세요.

### 날짜별 환영 문구 변경
`const DAY_INTRO={`에서 해당 날짜의 `t`(제목), `s`(설명)를 수정하세요.

### 테마 컬러 바꾸기
`css/style.css` 맨 위 `:root`에서 `--orange:#FF7A00;` 등을 변경합니다. 예: `--orange:#6E55D9;`. 다른 색상값은 곳곳에 직접 들어 있어 전체 일괄 변경은 디자이너 확인이 필요합니다.

## 4. 수정할 때 주의사항

- 문구는 **따옴표**(`"..."`) 또는 백틱(`` `...` ``) 내부에서 고치세요.
- 쉼표, 중괄호, 대괄호는 지우지 마세요. 문법 오류가 나면 화면이 빈 화면으로 보일 수 있습니다.
- HTML 태그 `<b>`, `<br>`은 각각 **굵게**, **줄바꿈**을 의미합니다.
- `kind:"type"` 문항의 선택지 **인덱스 0/1/2/3**이 각각 탐험가/완주러/말랑이/칭찬왕 점수와 연결됩니다. **선택지 수·순서를 임의 변경하지 마세요.**
- `map:true`는 중간 마음지도 표시입니다. 날짜별 질문 배치/개수 수정은 `app.js`의 흐름에 영향을 줄 수 있습니다.
- 시연 컨트롤러의 바로가기 및 샘플 친구/응답은 **실제 사용자 저장 데이터가 아닌 데모 데이터**입니다. 브라우저 새로고침 시 상태가 초기화됩니다.
- 이 파일은 **프로토타입**이며 실제 서비스 운영용 서버·인증·개인정보 저장 기능은 포함하지 않습니다.
- 공개 GitHub에 올릴 경우 내부 디자인·이미지·콘텐츠의 공개 허용 여부를 검토하고, 실제 아동의 개인정보는 추가하지 마세요.

## 5. 다른 사람과 GitHub에서 함께 수정하기

1. GitHub에서 새 저장소(repository)를 만듭니다. 공유 범위가 제한되어야 한다면 **Private**로 만드세요.
2. 저장소에서 **Add file → Upload files**로 압축 해제한 폴더의 파일과 폴더를 업로드합니다. (`index.html`이 저장소 루트에 있어야 합니다.)
3. 협업자를 **Settings → Collaborators**에서 초대합니다.
4. 각자 GitHub에서 파일 수정 또는 VS Code에서 `git clone`으로 가져와 작업합니다.
5. 수정은 가능하면 각자 **새 브랜치**에서 진행하고 **Pull Request**로 검토 후 병합합니다.
6. 공개 미리보기가 허용된다면 GitHub Pages 설정을 검토하세요. **Private 저장소의 Pages 공개 범위는 요금제·설정에 따라 다를 수 있습니다.**

### Git 사용 예시
```bash
git clone <저장소-주소>
cd <저장소-폴더>
git checkout -b edit/day1-copy
# config.js 수정 및 브라우저 확인
git add .
git commit -m "Day1 질문 문구 수정"
git push -u origin edit/day1-copy
```

## 7. QA 참고사항

원본의 로직을 최대한 유지하기 위해 **문구 설정/코드 분리 외에 기존 로직을 재설계하지 않았습니다.** 예를 들어 성향 답변을 같은 질문에서 여러 번 고르면 유형 점수가 중복 가산될 가능성이 있으며, 실제 운영 전에는 개발자 검증이 필요합니다. 이 프로젝트에서 제시하는 성향 결과는 임상적 진단으로 사용해서는 안 됩니다.
